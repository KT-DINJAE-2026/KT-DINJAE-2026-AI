- **작성자**: AI 파트

- **목적**: TCD 원본 데이터를 모델 학습용 데이터로 가공하기 전, "교통약자" 판별 기준과 "버스 유형" 필터링 기준을 확정하기 위한 분석 및 논의

## 3. 백엔드 요청 사항 — 학습용 승객 데이터 명부 스펙

한 행 = 승객 1명의 1회 탑승 기준으로 아래 형태의 명부 제작을 요청드립니다.

### (A) 입력 피처

| 피처 | TCD 원본 필드(번호) | 비고 |
| --- | --- | --- |
| 노선 | 필드24(국토부 노선ID) | 정산사ID(필드25)는 조인용 보조로만 |
| 승차 정류장 | 필드28(국토부 승차 정류장ID) | 프론트 `stopId`와 매칭되는 체계인지 재확인 필요 |
| 하차 정류장 | 필드30(국토부 하차 정류장ID) | 상동 |
| 요일 / 시각 | 필드9(승차일시)에서 파생 | 백엔드에서 파생해서 줘도 되고, 원본 승차일시만 줘도 AI가 직접 파생 가능 |
| 공휴일 | 외부 공휴일 API (백엔드 담당) | 승차일시 기준 boolean |
| 날씨 | 외부 기상 API (백엔드 담당) | 승차 시각·정류장 위치 기준 |
| 배차간격 | 별도 산출 필요 | TCD 자체엔 없음 — 같은 노선·정류장의 연속 차량 도착 간격으로 산출 |
| 버스 유형 | 필드45(정산사 교통수단코드) | **마을(105,151)/간선(115)/지선(120,121,122)만** — 위 2번 항목 확정 기준 |
| 사용자구분코드 | 필드34 | 02/04/05 교통약자, 국가유공자·일반인 포함여부는 위 1번 항목 미결 사항과 연동 |

### (B) 정답 레이블

TCD 원본에는 "입석여부", "입석시간" 컬럼이 존재하지 않아서 계산이 필요합니다. 이는 "재차인원 복원 → FIFO 좌석배정 시뮬레이션"을 거쳐서 만들어내는 파생값입니다.

| 레이블 | 설명 | 산출 방식(백엔드 담당) |
| --- | --- | --- |
| `is_standing` (Y/N) | 승차 시점에 좌석이 없어 입석했는가 | 같은 차량·같은 운행회차의 재차인원과 좌석수(버스유형별 20/25석) 비교 |
| `standing_seconds` | 입석 후 착석까지 걸린 시간(초) | FIFO 시뮬레이션(먼저 입석한 순서대로 좌석 배정)으로 산출, 입석 없었으면 0 |

→ 원본 TCD만 받으면 AI 쪽에서 운행회차 판별부터 FIFO 시뮬레이션까지 다시 짜야 하는데, 조심스럽게 **재차인원·좌석배정 시뮬레이션 결과를 승객 단위로 붙여서** 받을 수 있을지 요청드립니다.

### 파일 형식

- CSV보다 **parquet** 권장 (컬럼 수 많고 대용량 — I/O 효율)
- 결측치 표시 방식(빈 문자열 / NULL / 특정 코드) 통일 요청
